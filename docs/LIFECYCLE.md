# Управление задачами

Контракт команд — [SPEC.md](SPEC.md), переходы и формат данных —
[MODEL.md](MODEL.md). Состояние разработки и фактические результаты проверок
хранятся только в [PLAN.md](../PLAN.md).

## Команды над планом

`edit --id <id> --title <title> --description <text>` меняет только указанные
поля. Отсутствующий флаг сохраняет прежнее поле; `--description=""` очищает
описание. Пробельный title запрещён, непустой сохраняется буквально.
ID, номер, статус, связь, история завершений и перепривязок сохраняются.

`move --id <id>` требует ровно один из `--after <id>`, `--before <id>`,
`--end`. Опорная задача может быть archived. Отсутствующая опора или ссылка
на себя дают ошибку. Меняется порядок, а не ID/номер и не хвост вставки.

`pause --id <id> [--attempt <id>]` переводит выбранный active-подход в paused,
сохраняя его ID. Без селектора нужен единственный локально связанный
незавершённый подход; неоднозначность требует точный ID из show/status JSON.
Повтор paused не пишет план или backup. `archive --id <id>` сохраняет
все данные, включая незавершённые записи attempts, и освобождает живую связь
ветки. Архивный снимок не участвует в tracking. Ветка, код и commits
не удаляются; unarchive в первой версии отсутствует. Повтор archived — no-op.

Эти команды не переключают ветки, работают при staged/unstaged/untracked
коде и незавершённых Git-операциях. CLI разбирает аргументы и выводит результат;
переходы выполняет `task`, чтение/сохранение координирует `app` через `storage`.
Общая write.lock, проверка исходных байтов/ревизии и валидируемая замена плана
сохраняются. Любая мутация отказывает при незакрытом operation.json.

## Редактор

Без полевых флагов edit открывает UTF-8 JSON с двумя обязательными строковыми
полями `title` и `description`. Неизвестные, повторные, пропущенные и null-поля,
неверные типы и лишние данные запрещены.

Настройка выбирается в порядке GIT_EDITOR → core.editor → VISUAL → EDITOR.
Пустые/пробельные значения пропускаются. Ошибка чтения Git config возвращается
как ошибка; отсутствие настройки предлагает полевые флаги. Встроенного
редактора по умолчанию нет.

Настройка — имя исполняемого файла с аргументами, например `code --wait` или
`"C:\Program Files\Editor\editor.exe" --wait`. Пробелы разделяют аргументы вне
одинарных/двойных кавычек; кавычки снимаются. Внутри одинарных кавычек все
символы буквальны. В двойных кавычках `\"` означает буквальную кавычку;
остальные обратные слеши сохраняются, включая Windows-пути и UNC. Вне кавычек
обратный слеш экранирует пробельный символ или кавычку, иначе сохраняется.
Пустые аргументы допустимы, пустое имя программы, NUL и незакрытые кавычки —
ошибка. Подстановки переменных, `~`, конвейеры и shell-выражения не исполняются.
Для них можно явно настроить отдельный исполняемый скрипт-обёртку.

Редактор получает путь временного документа отдельным последним аргументом;
title/description не входят в команду. Рабочий каталог — корень репозитория,
stdin передаётся явно, stdout/stderr редактора идут в диагностический поток.
Оболочка не запускается. Редактор должен ждать закрытия документа; например,
для GUI с таким режимом нужен `--wait`. Основной план не открывается напрямую.

Снимок читается до запуска, блокировка не держится во время редактирования.
Ненулевой выход редактора/отмена context дают код 130, ошибка запуска — 1;
план не применяется. Успешный неизменённый документ — no-op.
Валидация и сохранение используют исходный снимок, поэтому даже изменение
другой задачи или форматирования plan.json конфликтует. При неверном документе
или отказе сохранения результат редактора оставляется по пути из диагностики;
при конфликте storage также сохраняет собственный кандидат `pending-*.json`.
Успешный/отменённый временный документ удаляется с проверкой ошибки удаления.
Гарантия не распространяется на любую гонку произвольного внешнего редактора.

## Resume и восстановление

`resume --id <id> [--attempt <id>]` принимает только paused-подход. Active даёт понятную ошибку
«уже запущена». Используется только связанная существующая локальная ветка,
сохраняются ID подхода, оригинальная ветка, наблюдения и attempts.
Нет случайного выбора, создания ветки или stash/reset/force.
В подключённом командном режиме сохранённые пользовательские мутации
пытаются опубликовать действие; отказ сети сохраняет очередь.

Отсутствующая/переименованная ветка и неподтверждённая непрерывность её reflog
требуют явного `attach <branch> --id <id> --rebind`. Недостаточная локальная
история даёт отказ. Повтор подтверждённого rebind — no-op, коллизия с другой
active/paused и target_branch запрещены. Старые доказательства работы сбрасываются,
ID подхода и история изменений связи сохраняются. Сходство SHA не восстанавливает
связь само по себе; переименование и пересоздание одного имени требуют подтверждения.

До переключения проверяются обычный HEAD, чистота рабочего дерева/индекса,
незавершённые операции, commit цели/связанной ветки и отсутствие tracked
`.git-task` в дереве назначения. Перед внешним эффектом под общей write.lock
записывается operation.json с исходными байтами, полным результатом paused →
active, ID операции, HEAD, последней записью HEAD reflog и отпечатком reflog
связанной ветки. Перед checkout эти факты и план повторно проверяются.

Checkout получает GIT_TASK_OPERATION для подавления собственного hook и
GIT_REFLOG_ACTION=`git-task resume <operation-id>` только в дочернем процессе.
Чужие hooks остаются включёнными. После checkout нужны точные HEAD/commit,
собственная последняя метка HEAD reflog, неизменные цель, tip и branch reflog.
После подтверждения одним обновлением сохраняется active, затем закрывается журнал.

Ошибка Git может возникнуть после переключения. При подтверждённом эффекте
сохраняется active и сообщается «задача уже продолжена», но код остаётся ненулевым.
При доказанном отсутствии эффекта журнал закрывается без записи плана.
После отмены короткий диагностический context ограничен 30 секундами; сохранение
использует исходный context. При отмене/сбое после переключения план может
остаться paused с журналом, а после записи до закрытия — active с журналом.
Ненулевой код не означает откат Git; операция не повторяется автоматически.

Общий `app.RecoverStart` обслуживает и resume; CLI doctor предоставляет
`doctor --repair recover-start` по протоколу [DOCTOR.md](DOCTOR.md).
При точном исходном плане и неизменённых Git-фактах до checkout закрывается
только журнал, задача остаётся paused. При точном исходном плане и собственном
подтверждённом checkout сохраняется подготовленный active. При уже установленном
точном результате закрывается только журнал, без повторной записи/смены backup.
Чужая правка плана, ветки/цели/reflog или неподтверждённое владение — отказ;
журнал сохраняется. После очистки журнала повтор восстановления — no-op.

## Повторная работа

`complete --id <id> [--attempt <id>] [--commit <oid>] [--yes]` использует общий
ручной переход выбранного подхода. Задача done только при непустом наборе
всех известных подходов done. Done без нового commit — no-op; новое
доказательство для done — ошибка.
После ручного или автоматического done используйте
`start <new-branch> --id <id> --again` либо точный `--title <title> --again`.
Предыдущие attempts сохраняются, done переходит прямо в active, создаётся
новый подход. Старое доказательство не закрывает новую пустую работу.
После наблюдения новой работы и merge/fast-forward добавляется ровно одна
завершённая запись нового подхода. Ошибка до создания ветки сохраняет done.

## Карта подготовленных проверок

Запуск принадлежит независимому проверяющему; наличие сценария не означает
пройденную проверку. Помимо базовых vet/test/build:

| Контракт | Файлы сценариев |
|---|---|
| Dirty код, ID/номер, no-op, archive/освобождение ветки, edit/move конфликт | `internal/app/lifecycle_test.go` |
| Ручной done → again по ID/title → pause/resume → merge/ff → повтор sync | `internal/app/lifecycle_again_test.go` |
| Resume, отсутствующая/переименованная/пересозданная ветка, ошибка hook и восстановление | `internal/app/resume_test.go` |
| Синтаксис до открытия репозитория, help, последовательность CLI, редактор/конфликт | `internal/cli/lifecycle_test.go` |
| Реальный дочерний редактор, отдельный путь с пробелами, потоки, отмена/ошибка | `internal/cli/editor_test.go` |
| Приоритет и отсутствие настройки редактора, ошибка Git config | `internal/git/editor_test.go` |
| Реальный бинарник через git task, move/edit, pause/resume, complete/again/merge и rebind/archive | `cmd/git-task/lifecycle_test.go`, вызов из `TestBinaryCommands` |
| Сохранность обычного merge/ff и again; запреты/конфликты rebind, сброс старого доказательства | Существующие `internal/app/sync_test.go`, `internal/app/attach_test.go`, `internal/app/start*_test.go` |

Windows/Linux/macOS проверяются исполнением, а не одной кросс-компиляцией.
