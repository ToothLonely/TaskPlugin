# Разработка git-task

Состояние и результаты этапов находятся только в [PLAN.md](../PLAN.md).
Контракт продукта — [SPEC.md](SPEC.md), технические решения — [DECISIONS.md](DECISIONS.md).

Для исходников выбран локальный модуль `git-task`: адрес опубликованного
репозитория пока не назначен. Внешних Go-зависимостей нет, поэтому go.sum не нужен.
База разработки — Go 1.26 и Git 2.51; проверяемые платформы выпуска определяет
матрица P15/P17. Более старые версии пока не заявлены. Сборка и тестирование
на одной ОС не подтверждают поддержку остальных ОС.

При доступных Go и Git:

~~~text
go vet ./...
go test -count=1 ./...
go build ./...
go build -o bin/git-task ./cmd/git-task
~~~

На Windows выходной файл — `bin/git-task.exe`. Запускать можно прямо по пути
к бинарнику. Для `git task` каталог бинарника должен быть в PATH текущего
терминала. Глобальная установка не требуется. Версия по умолчанию — `dev`;
её можно задать при сборке: `-ldflags=-X=main.version=0.1.0`.

Для локального Go в `.tools/go` на Windows команды ниже удерживают кеши и
временные репозитории в проекте. Переменные действуют в текущем терминале:

~~~powershell
New-Item -ItemType Directory -Force .tools/tmp | Out-Null
$env:GOCACHE = "$PWD/.tools/gocache"
$env:GOMODCACHE = "$PWD/.tools/gomodcache"
$env:GOPATH = "$PWD/.tools/gopath"
$env:GOTMPDIR = "$PWD/.tools/tmp"
$env:TEMP = "$PWD/.tools/tmp"
$env:TMP = "$PWD/.tools/tmp"
$env:GOENV = 'off'
$env:GOTOOLCHAIN = 'local'
$env:GOTELEMETRY = 'off'
.tools/go/bin/gofmt.exe -w cmd internal
.tools/go/bin/go.exe vet ./...
.tools/go/bin/go.exe test -count=1 ./...
.tools/go/bin/go.exe build ./...
.tools/go/bin/go.exe build -o bin/git-task.exe ./cmd/git-task
~~~

`.tools/` и `bin/` исключены из исходников. Это инструменты разработки, а не
хранилище плана продукта; CLI не меняет `.gitignore` для хранения задач.

## Границы каркаса

- `cmd/git-task/main.go` соединяет сигналы отмены, потоки процесса и CLI.
  `os.Exit` вызывается после возврата `run`, когда его defer уже выполнены.
- `internal/cli` реализует help/version/init/add/start/attach и текстовый status, синтаксические
  ошибки, коды выхода и явные потоки. Справка не открывает репозиторий.
  Status пока читает сохранённый план; tracking и --json — P09/P12.
- `internal/app` соединяет Git, модель задач и сохранение. Зависимости собираются
  через функцию открытия, переданную из main; при ошибке синтаксиса она не вызывается.
- `internal/storage` читает/пишет единственный plan.json с проверкой снимка,
  блокировкой и резервной копией. Протокол и ограничения — [STORAGE.md](STORAGE.md).
- `internal/git` находит исполняемый Git и запускает его с контекстом,
  отдельными аргументами и раздельными stdout/stderr. Отсутствие Git возвращает
  `ErrUnavailable`; ошибка выполнения сохраняет `CommandError` и исходный
  `exec.ExitError`. Ненулевой код всегда сопровождается ошибкой, а ожидаемый
  отрицательный результат конкретного запроса распознаётся вызывающей операцией.
  Например, только для `merge-base --is-ancestor` код 1 означает «не предок».
- `Discover` возвращает абсолютные корень, git directory, common directory и
  info/exclude, в том числе из вложенной папки/unborn/detached. Bare отклоняется.
  CheckStorage отдельно отклоняет shallow/partial/additional worktrees и путь
  метаданных, отслеживаемый в HEAD или индексе.
- `BranchRef` проверяет короткое буквальное имя и возвращает полный ref.
  Низкоуровневый `Run` принимает только аргументы от кода адаптера/доверенного
  вызывающего кода: передавать туда сырые аргументы CLI запрещено.

Адаптер запрещает Git transport (`GIT_ALLOW_PROTOCOL=`), lazy fetch и
терминальные запросы Git. Это не песочница для произвольных сторонних hooks.
Отмена завершает процесс Git; удерживаемые потомком pipe ограничены WaitDelay.
Уничтожение всего дерева сторонних процессов и откат уже совершённых эффектов
не обещаются. Start/attach используют журнал и проверку фактического состояния;
протокол и восстановление — [START.md](START.md).

## Тесты

Git-тесты требуют реальный Git: отсутствие не считается пропуском успешной
проверки. Помощник `internal/git/testrepo_test.go` создаёт собственные config,
identity, hooks и пустой template; убирает унаследованные GIT_* и перенаправляет
HOME/USERPROFILE/XDG_CONFIG_HOME. Он не читает пользовательские credentials.
Тест изоляции намеренно задаёт чужие GIT_DIR/index/config в своём временном
каталоге и проверяет их сохранность. Тест транспорта использует локальный file
URL, поэтому не обращается в сеть даже при дефекте запрета.

Тест бинарника собирает CLI во временный каталог, проверяет реальные коды
выхода вне репозитория и без Git в PATH, затем вызов `git task version` через
Git `--exec-path`. Тест отмены процесса использует дочерний Go test-бинарник;
Git-семантика (ancestry, refs, пути) проверяется настоящим Git.

### Linux-проверка из Windows через Docker

При доступном Docker Engine для Linux запустить из PowerShell:

~~~powershell
./scripts/check-linux.ps1
# Без подготовки образа и сетевых загрузок, если образ уже существует:
./scripts/check-linux.ps1 -UseExistingImage
# Если docker не находится в PATH:
./scripts/check-linux.ps1 -Docker '<полный путь к docker.exe>'
~~~

Сценарий создаёт локальный образ `git-task-checks:go1.26.8-git2.51.0`.
Это изменяет хранилище Docker; при ограничении записей за пределами проекта
сначала требуется разрешение владельца. Подготовка образа использует сеть:
база Go закреплена digest, Git 2.51.0 собирается из официального архива с
проверкой SHA-256, системные зависимости устанавливаются внутри образа.
Зависимости Debian не закреплены по snapshot, поэтому образ не заявлен как
побайтово воспроизводимый; версии Go/Git зафиксированы.

Тестовый контейнер работает без сети, от непривилегированного пользователя,
с корневой файловой системой только для чтения. Монтируются только `go.mod`,
`cmd` и `internal` в режиме чтения. Копия кода, кеши, бинарники и временные
репозитории находятся в Linux tmpfs; свойства регистрозависимых путей не
проверяются на Windows bind mount. Контейнер удаляется после завершения,
подготовленный образ остаётся для повторного запуска.

`scripts/check-linux.sh` последовательно выполняет vet, полный тестовый прогон
без кеша, build, адресные тесты регистра/symlink и race для storage/cli/git/app.
Ошибка любой команды завершает сценарий с ошибкой. Windows-регрессии
регистронезависимых путей нужно запускать отдельно. Успешный Linux race не
устанавливает причину антивирусного детекта Windows EXE и не подтверждает
поддержку macOS; матрица P15/P17 остаётся обязательной.
