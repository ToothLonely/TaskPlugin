# Модель задач и JSON

Контракт поведения — [SPEC §5–7](SPEC.md), реализация — `internal/task`.
Пакет не обращается к Git, файлам или терминалу. Методы изменяют план в памяти.
Пример минимального документа схемы 1:

```json
{
  "format": "git-task",
  "schema_version": 1,
  "revision": 0,
  "target_branch": "main",
  "order": ["task-a"],
  "tasks": [
    {"id": "task-a", "number": "T-001", "title": "Профиль", "revision": 0, "status": "todo"}
  ],
  "last_event": 0
}
```

## Структура

| Поле | Назначение |
|---|---|
| `format`, `schema_version` | Принадлежность формату `git-task`, версия `1`; неизвестная версия отклоняется |
| `revision` | Беззнаковая 64-битная ревизия плана; у каждой задачи своя ревизия |
| `target_branch` | Буквальное короткое имя целевой локальной ветки |
| `order` | Каждый ID ровно один раз, включая archived; единственный источник порядка |
| `tasks` | Массив задач; его физический порядок не определяет выбор первого todo |
| `last_event` | Максимальный номер завершения, 0 без истории |
| `insertion_tail` | ID хвоста будущих вставок; после завершения равен ID завершённой задачи |

ID и отображаемый number — непустые строки без управляющих символов, уникальные
в плане. Это отдельные значения, не позиции и не алиасы друг друга. Пакет
принимает готовые идентификаторы; их выдача при add/import/start принадлежит
вызывающим операциям. Нужна независимая от часов уникальность, например случайный
ID подхода и сохраняемый счётчик отображаемых номеров. Валидация отклоняет
повторный ID подхода во всём плане, включая архив и историю.
Заголовки могут совпадать, сохраняют Unicode, регистр и крайние пробелы;
пустой/пробельный title запрещён. Description необязателен.

`active_attempt` и элемент `attempts` имеют общий тип `Attempt`:

| Поле | Назначение |
|---|---|
| `id` | Постоянный ID подхода, сохраняется при pause/resume/rebind/complete |
| `branch`, `original_branch` | Текущая и исходная ветки |
| `target_branch`, `base_commit` | Цель подхода и commit основания текущей связи |
| `started_at` | Известное время начала |
| `rebindings` | Последовательность `{from, to, base_commit, observed_at}` |
| `completion` | Только для завершённого подхода |

У связанного подхода обязательны все поля связи, основание и время начала.
Branch не может совпадать с target. Rebind сохраняет исходную ветку и ID,
добавляет последовательную запись и заменяет основание свежим наблюдением.
Две живые задачи in_progress/paused не могут занимать одну ветку; archived
сохраняет снимок, но не занимает её. Историческая связь не является живой.

`completion` содержит `event`, `source`, `target_branch`, необязательные
`completed_at`, `observed_at`, `commit`, `merge_kind`, `work_commit`:

- `manual`: явное решение пользователя. Commit необязателен; без текущей
  работы создаётся запись с ID и completion, без ветки, основания и начала.
- `imported`: импортированное завершение без выдуманных Git-полей и дат.
  Известные даты полного JSON-снимка можно сохранить.
- `merge`: требуется связанный подход, полный `commit` цели, `work_commit`,
  `observed_at` и вид `merge_commit` либо `fast_forward`. Модель проверяет
  структуру; истинность и достаточность доказательств проверяет tracking P09.
  Squash не является допустимым видом merge.

OID — ненулевое полное 40- или 64-значное шестнадцатеричное значение в нижнем
регистре. Структурная проверка имени ветки/OID не доказывает существование
или достижимость. Это отдельная обязанность Git-адаптера и app.

## Переходы и границы вызова

`Start(id, attempt, again)` получает уже разрешённый постоянный ID. Todo
допускает обычный start, done — только again. Оба пути --id/--title сводятся
к этому методу; проверка конфликтующих CLI-селекторов и обязательного имени
ветки реализуется в P06. До вызова Start приложение проверяет условия и
устанавливает фактический результат Git-операции.

`Attach` принимает только todo. `Pause` сохраняет текущий подход, повтор paused
— no-op. `Resume` принимает только paused и применяется после успешного
переключения Git. `Archive` замораживает данные; повтор archived — no-op.
`Rebind` принимает in_progress/paused; повтор той же подтверждённой ветки — no-op.
Свежие наблюдения после rebind не наследуют доверие старой связи.

`Complete` принимает ID подхода и завершение с `event=0`; назначает следующий
event, переносит подход в историю, очищает active_attempt и ставит done за одно
изменение памяти. Для todo разрешены manual/imported с новым ID, для текущей
работы — manual/merge с её ID. Повтор того же исторического события — no-op,
в том числе после нового start. Изменение source/цели/Git-доказательств старого
события даёт ошибку; время повторного обнаружения игнорируется. Событие другого
подхода не завершает текущий. `CompleteManual` дополнительно реализует правило
команды: complete для done без commit — no-op, с commit — ошибка.

Каждый успешный переход увеличивает ревизию плана и затронутой задачи один раз.
Ошибка/no-op не меняют ничего. Операция проверяет исходный план, изменяет копию
задачи, валидирует итог и только затем заменяет план. Входные даты/срезы и
результаты FindID/FindTitle не сохраняют изменяемых ссылок на чужие данные.
Структуры открыты для storage/import/P04: прямые изменения требуют Validate
и сами не являются защищённой операцией.

`SetWarnings` сохраняет `{code, message}`, не меняя статус или подходы.
Предупреждение об отсутствующей ветке не означает done/archived. Смена связи,
новый подход и завершение очищают прежнюю диагностику.

## Порядок событий и даты

Event — положительный uint64, уникальный во всём плане; история каждой задачи
возрастает по event. Пробелы допустимы, но last_event равен максимуму истории.
Следующий event — last_event + 1; переполнение даёт ошибку без изменений.
Часы не определяют ID, порядок или уникальность. Одинаковые даты и перевод
часов назад допустимы; неизвестная дата отсутствует. Известные даты имеют формат
RFC3339/RFC3339Nano, сохраняют часовой пояс; нулевая дата запрещена. Часы
смещения — 00–23, минуты — 00–59; проверяется исходная строка до нормализации
парсером времени. Для дат из Go API смещение должно быть строго внутри ±24 часов
и кратно минуте: секундная часть не представима в RFC3339 и не отбрасывается молча. Время
реального завершения отдельно от времени обнаружения.

При групповом обнаружении неизвестного порядка sync/import применяет Complete
последовательно в порядке плана/строк. Межпроцессная блокировка — P05. Правила
вставок/move и выдача номеров — P04; модель сохраняет явный порядок и хвост,
не переставляя задачи при завершении.

## Чтение и запись JSON

`json.Marshal(Plan)` и `json.Unmarshal(data, &plan)` проверяют полный снимок.
Неуспешное чтение оставляет прежний объект без изменений. Отклоняются неизвестные
поля/статусы, повторные ключи, иной регистр ключей, неправильный UTF-8,
непарные UTF-16-суррогаты в Unicode-escape, null,
неверные связи/истории, переполнение чисел и лишний JSON. Ревизии и last_event
обязательны даже при нуле. Order/tasks — массивы, в том числе пустые.
Необязательные пустые массивы attempts/warnings/rebindings должны отсутствовать.
До первого завершения `attempts` отсутствует, не `[]` и не `null`. У done история
непуста и active_attempt отсутствует. Start --again сохраняет историю.
Unicode-escape проверяются до декодирования строк: корректные пары, настоящий
U+FFFD и буквальный текст `\\ud800` допустимы, повреждённые пары не заменяются на `�`.

Это формат данных в памяти, без файлового I/O. Ревизия и копирование не заменяют
блокировку, проверку исходного содержимого, backup, журнал или безопасную замену
P05/P06. Доказательства tracking могут потребовать явного развития схемы на P09;
текущие поля не объявляются готовым алгоритмом автоматического done.
