# Git Task — приёмочные сценарии

Контракт: [SPEC.md](SPEC.md); причины выбора деталей: [DECISIONS.md](DECISIONS.md). Это нумерованные ожидаемые сценарии, не отчёт о запуске приложения. Текущее состояние проверок — в [PLAN.md](../PLAN.md). P15 свяжет каждый сценарий с реальным тестом или воспроизводимой ручной проверкой; необходимые тесты каждого изменения пишутся на его этапе.

## Условия и обозначения

Для Git-сценариев нужен настоящий Git и отдельный временный репозиторий с локальной identity/config/hooks; исключить global/system config и унаследованные указатели GIT_* на чужой репозиторий. Не читать credentials, не менять настройки пользователя. Тесты отказов сравнивают refs, HEAD, индекс, содержимое кода и plan.json до/после, а не только сообщение. Допустимые последствия прерывания (журнал/созданная ветка) указаны отдельно. Сетевые вызовы запрещены во всех локальных сценариях.

`A`, `B`, `C` — постоянные ID отдельных задач; в примерах CLI использовать эти строки буквально либо заданные task-001 и т. п. Порядок списка отделён от состояния. По умолчанию target_branch=main с начальным commit O, план инициализирован, дерево чистое, hooks установлены, каждая история независима. «Без изменений» означает отсутствие эффектов команды в Git/плане/истории; у искусственно внесённых внешних изменений должен сохраниться их собственный эффект.

### Минимальные графы для A046–A054

Буквы — commit ID; стрелка означает родителя слева, а не время по часам. Наблюдение работы снимается до интеграции, кроме явно пропущенных событий.

~~~text
A046: main=O, feature=O. Нет нового commit.
A047: O--M (main); feature продвинута до M только из main.
A048 fast-forward: O--W (feature), main сначала O, затем W.
A048 merge: O--M--J (main); O--W (feature); родители J = M,W.
A049 конфликт: тот же разошедшийся граф, J ещё не существует.
A052 squash/cherry-pick: O--S (main), O--W (feature); W не предок S.
A053: O--W--N (feature); main интегрировал W, но не N.
A054: сохранён W, feature теперь W2 после переписывания либо имя
      feature удалено/создано заново; старый W достижим из main.
~~~

### Матрица восстановления A072 (регрессия P01-R01)

Во всех первых четырёх строках Git-эффект уже произошёл, подготовленный plan.json успешно сохранён, а процесс прерван до закрытия журнала J. Снимки «до» и «после» связаны с ID операции J; текущее Git-состояние соответствует её результату. Сравнивать данные перед repair с данными после repair, а не с состоянием до запуска. Вызвать `doctor --repair recover-start --yes`.

| Случай | Уже сохранённый результат | Ожидаемое восстановление |
|---|---|---|
| Первый start для todo A | A=active, active_attempt=P из J, attempts отсутствует | Только закрыть J; сохранить тот же P, отсутствие attempts, байты/revision plan.json и backup; ни создания ветки, ни переключения заново |
| Start --new | Новая задача A и её номер/место в порядке уже записаны, active_attempt=P, attempts отсутствует | Только закрыть J; не создавать вторую задачу/номер, не повторять вставку, сохранить хвост группы, P, plan.json и backup |
| Start --id A --again или эквивалентный --title для done | A=active, новый P из J; прежняя история H сохранена | Только закрыть J; не создавать ещё один подход, не дописывать/стирать H, не менять ревизию/байты плана или backup |
| Resume paused A | A=active с прежним P и той же историей H, HEAD на связанной ветке | Только закрыть J; не переключать снова, не заменять P, не менять H, ревизию/байты плана или backup |

Для каждой строки проверить повтор repair после закрытия: код 0, «Нет незавершённой операции», без подтверждения и любых изменений. Затем выполнить разрешённую чистую операцию плана, например add: она больше не блокируется закрытым J.

Отдельные негативные и граничные варианты A072:

- После сохранения результата до repair внешний редактор меняет title A или другую задачу плана, в том числе без увеличения ревизии. Даже при совпадающих P/ветке/статусе текущий файл не равен подготовленному результату: отказ, внешний файл и J сохранены, Git/attempts/backup не меняются. --yes не обходит проверку.
- План уже отличается от исходного, а подготовленный отпечаток/описание результата в J отсутствует или повреждён либо фактический Git-эффект нельзя подтвердить: отказ без угадывания по одному active/P. Конкурентная замена J на другое намерение не приводит к закрытию чужого журнала.
- План ещё равен исходному снимку и Git-эффект J подтверждён: repair сохраняет результат один раз. Если repair прервать после этой записи до закрытия J, следующий repair выполняет только закрытие, как в четырёх строках выше.
- План равен исходному снимку и подтверждено отсутствие Git-эффекта: только закрыть J без запуска/переключения, оставить исходный статус, историю и ревизию.
- Ошибка закрытия J после подтверждения уже сохранённого результата: ненулевой код с точным сообщением о сохранённом плане, без отката. После устранения ошибки повтор закрывает J без повторной записи плана; следующий повтор — no-op.

На P01 матрица проверяется на бумаге. Fault-injection на границе записи/закрытия, сравнение refs/HEAD, байтов плана/backup и истории — обязательные программные проверки соответствующих P05/P06/P11/P14, а не выполненные здесь тесты приложения.

## Сквозной маршрут первой версии (P15–P17)

A076. В изолированном проекте выполнить init и import с `[x]`/`[ ]`, отдельно hooks install. Запустить первый todo, добавить собственный commit, выполнить обычный merge в main и получить автоматическое done. Добавить два пункта после последнего завершения, явно запустить один по --title, второй автоматически из его ветки: основания обоих — main. Один подход pause/resume, другой интегрировать fast-forward с пропущенным post-merge. После перерыва status восстанавливает доказанное завершение и показывает оставшуюся работу. Завершённый пункт запустить с --id --again, слить и проверить две записи attempts. Экспортировать JSON, проверить сохранность кода/индекса и uninstall без удаления плана. Отдельно воспроизвести прерванный start и безопасное восстановление. Итог связан с точной версией кандидата и фактическими запусками ОС; remote sync и ручной squash в маршрут не входят.
